# ROADMAP

## 해상도 원칙

이 문서는 **전 구간을 지휘하되 전 구간을 확정하지 않는다.**

| 구간 | 상태 | 해상도 |
|---|---|---|
| 현재 페이즈 | 확정 | 태스크 + 완료 조건 + 검증 커맨드 |
| 다음 페이즈 | 초안 | 태스크 목록 + 수용 기준 |
| 그 이후 | 목표만 | 게이트에서 통과한 뒤 채운다 |

앞 페이즈 결과가 뒤를 바꾸기 때문이다. 특히 G1(팔로워)과 G2(모델)는
확정 전까지 P3 이후를 세밀하게 쓰는 게 의미가 없다.

---

## 게이트

게이트에서 CLI는 **반드시 멈추고 사용자 승인을 받는다.** 그 외에는 혼자 진행한다.

| ID | 위치 | 판단할 것 | 승인 없이 진행 시 리스크 |
|---|---|---|---|
| **G0** | P0 종료 | 계약 스키마 확정 | 이후 전부가 잘못된 계약 위에 쌓임 |
| **G1** | P1 중반 | Apify 팔로워 필드 유무 → 지표 축 결정 | 버킷 설계 전체가 무의미해짐 |
| **G2** | P2 종료 | 비전 모델 실측 비교 → Claude/Gemini 확정 | 비용·품질 둘 다 최적화 실패 |
| **G3** | P3 종료 | 차이 문장 품질 → 임계값·n 가드 조정 | 노이즈를 "공식"으로 출력 |
| **G4** | P4 종료 | 리포트 실물 → 프롬프트 재작업 여부 | 제품의 심장이 목업인 채로 완성 |
| **G5** | P5 중반 | UI 흐름·상태 표현 | 15분 잡을 못 견디는 UX |
| **G6** | P7 | 실키 전환·배포 | 비용 사고 |

## 페이즈

### P0 — 뼈대 · 계약 · 잡 시스템 【확정 · `phase-0.md` 참조】

스캐폴드, Pydantic 계약, DB DDL, 잡 생성/조회/heartbeat, provider 인터페이스, 워커 루프 골격.
**검증**: 헬스체크 통과 + 빈 잡 생성→조회→stale 복구 시나리오 통과 + `make check` 그린.
→ **G0**

---

### P1 — 수집 · 실측 · fixture 박제 【초안】

- T-1.1 **실제 Apify 1회 호출** → 원본 JSON 전량 `fixtures/`에 박제 → 팔로워 필드 보고 → **G1**
- T-1.2 (G1 결과에 따라) 프로필 액터 2차 호출 + `accounts` 30일 캐시
- T-1.3 관련성 필터 (키워드 vs 캡션/해시태그/계정명/위치)
- T-1.4 **최근 30일 필터**
- T-1.5 캡션 유사도 중복 제거
- T-1.6 지표 계산: 반응률(필수) / 도달배수(팔로워 있을 때만)
- T-1.7 버킷 분류 + 트랙 선정 (돌파형 / 대형형 / 대조군)

**수용 기준**: fake 모드로 키워드 1개 → 돌파형 N개 + 대형형 N개 + 같은 버킷 대조군이 나온다.
수집량 목표 150~200 (30일 필터 후 실질 n 확보용).

---

### P2 — 컷 분해 · 샷 분석 【초안】

- T-2.1 ffmpeg scene detect → 실제 컷 경계 타임스탬프
- T-2.2 컷별 대표 프레임 1장 추출 + phash 중복 제거
- T-2.3 VLM 샷 서술 (구도/피사체/자막텍스트/움직임/의도)
- T-2.4 **Claude vs Gemini 실측 비교** (비용/지연/스키마 준수율/자막 OCR 정확도) → **G2**
- T-2.5 분석 결과 캐싱 (같은 릴스 재분석 금지)
- T-2.6 분석 후 mp4 즉시 삭제

**수용 기준**: 릴스 1개 → 샷 배열. 모든 `t_start < t_end`, 컷 수는 ffmpeg 값과 일치.

---

### P3 — 대조 분석 【목표만】

같은 버킷 내 고성과 vs 저성과 특성 비교. 시간축 통계(첫 컷 길이, 평균 샷 길이, 컷 수).
**n < 15면 차이 문장을 생성하지 않고 "패턴 불충분"을 반환**하는 가드가 핵심.
출력은 퍼센트가 아니라 "18개 중 14개".
→ **G3**

---

### P4 — 가이드 생성 【목표만】

Claude가 4분할 산출물 작성. 돌파형 → 샷리스트·촬영팁 / 대형형 → 음원·소재·해시태그.
사용자 제약(혼자 촬영/장비/공간/얼굴 노출)으로 재현 불가 기법 필터링.
→ **G4**

---

### P5 — 내 릴스 진단 【목표만 · 우선순위 상향】

URL 입력 → 내 릴스 분석 → 상위 릴스 평균과 갭 카드.
**리텐션의 핵심.** 트렌드 리포트는 매주 비슷하지만 이건 매주 다르다.

---

### P6 — 프론트엔드 【목표만】

입력 → 진행률(단계별) → 결과 4분할. 로딩/에러/빈 상태 전부 정의 필요.
→ **G5**

---

### P7 — 실키 전환 · 배포 【목표만】

`*_MODE=fake` → `real` 스위치. ffmpeg 설치 가능한 호스팅. 비용 상한·레이트리밋.
→ **G6**
