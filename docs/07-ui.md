# 07 — UI

> **스켈레톤 문서.** P6 진입 시 G5에서 상세화한다.
> 지금은 화면 구성과 필수 상태만 정의한다.

## 화면 3개

```
① 입력  →  ② 진행  →  ③ 결과
```

### ① 입력

- 키워드, 업종
- 촬영 조건 (혼자 촬영 / 장비 / 공간 / 얼굴 노출 / 주당 시간)
- 내 릴스 URL (선택)
- [분석 시작] → `POST /api/analyses` → 진행 화면으로

### ② 진행 — **여기가 UX의 승부처**

5~15분 걸린다. 빈 스피너를 15분 보여주면 사용자는 이탈한다.

- 단계별 진행 표시 (수집 → 점수 → 다운로드 → 분석 → 비교 → 작성)
- `analyzing` 단계는 `7/20` 형태로 개별 진행 표시
- 2초 폴링
- 예상 소요 시간 안내
- 이탈해도 되게: URL에 job_id 포함, 나중에 다시 열면 이어서 보임

### ③ 결과 — 탭 4개

| 탭 | 내용 |
|---|---|
| 샷 리스트 | 컷별 표. **모바일에서 그대로 보며 촬영 가능한 레이아웃** |
| 자막 카피 | 카드 3~5개, 복사 버튼 |
| 음원 | 제목 + "12개 중 4개" 사용 표기 |
| 진단 | 내 릴스 vs 벤치마크 갭 카드 (내 릴스 없으면 탭 숨김) |

상단에 `evidence_note` + `confidence` 배지 상시 노출.
`confidence != "충분"`이면 `caveat`을 눈에 띄게 표시한다. **숨기지 마라.**

## 모든 화면 필수 상태

| 상태 | 처리 |
|---|---|
| 로딩 | 스켈레톤 |
| 에러 | 사람 말로 된 메시지 + 재시도 버튼. 스택트레이스 노출 금지 |
| 빈 상태 | "수집된 릴스가 없습니다" + 원인 안내 (키워드가 너무 좁음 등) |
| 표본 부족 | 결과는 보여주되 한계를 명시 |

## 원칙

- 모바일 우선. 사장님은 촬영 현장에서 폰으로 본다
- 점수·차트를 전면에 두지 않는다. **지시서가 주인공이다**
- 없는 데이터를 그럴듯한 UI로 채우지 않는다
